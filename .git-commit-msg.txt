fix(login): product-agnostic session capture for TeXPage deployments; non-blocking login UX

tex.nju.edu.cn is a TeXPage-based deployment, not standard Overleaf: its
session cookie names differ and the dashboard path is not /project, so the
CDP capture loop never satisfied its detection conditions and hung until
timeout, while the toolbar button stayed wedged for up to 15 minutes.

- login-cdp.ts: capture succeeds on (1) any non-preference cookie for the
  configured host, (2) a tab outside the origin's login/SSO pages, and (3) a
  tolerant server-side check; closing the login window aborts immediately.
- cookie-validate.ts: shared tolerant validation (200, 3xx away from login
  pages, or 404 when the probe route does not exist) used by both the CDP
  flow and the paste-cookie route.
- service.ts: /overleaf/workbench/login now returns immediately and runs the
  CDP flow in the background; new /login-status route exposes running state,
  elapsed time, result, and error.
- view.tsx: login start + 3s status polling; frame-bust detector surfaces a
  hint when the embedded document navigates itself out of the proxy.
- docs: bilingual README restored after a UTF-8 mojibake regression and
  updated for TeXPage support; version 0.1.2.
